# SilverBullet Knowledge Base

This context defines the vocabulary for an agent skill that writes user-approved, high-value documents to a personal SilverBullet knowledge base and retrieves them with full-text and structured search.

## Language

**Capture**:
The explicit user-invoked operation that writes a selected document into the KB. A capture writes immediately after validation; it does not perform an automatic value judgment.

**Update**:
The explicit operation that modifies an existing KB page identified by a path, page link, or unique title. Updates read the latest revision and use conditional writing; capture never silently turns into an update.

**Search query**:
The temporary words and filters used to retrieve documents for the current question. A query may use full-text terms or exact structural filters and is not itself stored as a tag.

**Knowledge directory**:
The dedicated top-level `Knowledge/` directory that stores captured knowledge documents in a flat layout. Agent retrieval defaults to this scope and excludes SilverBullet system content unless the user asks for a whole-Space search.

**Storage path**:
The machine-facing path generated by the skill under `Knowledge/`. It identifies the SilverBullet page for file operations and may differ from the document's display title.

**Display title**:
The first H1 in the captured document, preserved from the upstream artifact and shown to readers. The skill may generate a readable slug and short collision suffix for the storage path without rewriting this title.

**System content**:
SilverBullet libraries, plug bundles, configuration pages, templates, and repository catalogs that support the Space itself. System content is excluded from default knowledge retrieval.

**Source**:
The project that produced the document. Resolve it from the Git remote repository name, then the Git root directory name, and use `unknown` when neither can be confirmed.

**Type**:
The primary knowledge shape of a document. Each document has exactly one type tag. The initial types are `experience` for a lived engineering process and `research` for a systematic investigation or source-based analysis; the set is open to user-declared additions.

**Topic**:
The core subject a document teaches or records. A document has one to three topic tags, written as lowercase kebab-case slugs, with existing tags preferred over new synonyms.

**Tag role**:
The stable purpose of a tag namespace: `source` identifies provenance, `type` identifies knowledge shape, and `topic` identifies subject matter.

**Experience**:
A document whose primary evidence comes from a real development, debugging, design, or operational experience.

**Research**:
A document whose primary evidence comes from a systematic investigation, comparison, or analysis of sources rather than a single lived execution.

**Unknown type**:
A user-explicitly supplied `type/<slug>` that is not yet present in the KB inventory. It may be written without changing the skill; an agent-inferred new type requires user confirmation.
